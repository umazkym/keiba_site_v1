# 気づきの記録（複数の作業員で進めるとき）

作業員の報告・指揮役の点検・利用者の指摘から出た気づきを、ここ1か所に書く。返す先の決め方は `agent-sops/multi-agent-orchestration.sop.md` の 8。

- 書くのは指揮役（作業員は報告に書く）。新しい物を上に足す。1件は5行まで。
- 「返した先」が「記録だけ」の項目は、同じ事がもう1回出たら SOP かひな形を直す。
- 反映が済んで古くなった項目は消してよい（git の履歴に残る）。
- 鍵・トークンの値、メールアドレス、支払いの個人情報は書かない。

書く形：

```
## <記録した日> <一言の題>
- 出どころ：<作業員（担当）｜指揮役｜利用者>
- 起きたこと：
- 学び：
- 返した先：<記録だけ｜直した SOP・ひな形・道具・記憶の名前>
```

## 2026-10-02 画面を撮る道具と測る道具を、作業員に作らせて指揮役が見る
- 出どころ：作業員（画面を撮る・CLS を測る）と指揮役
- 起きたこと：ビルドと 3100番の起動は指揮役が1回だけ行い、作業員2人は読むだけにした。撮る側は9場面・26枚（約100秒）、測る側は27件（約6分）。作業員が目で見た画像は2枚だけで、残りは寸法の数字で報告した。
- 学び：
  - 道具は、行き先が 127.0.0.1／localhost でなければ通信の前に止める形にする（本番へ行かない）。
  - 寸法（枠の幅と本文の幅など）を数字で報告させると、指揮役が画像を開く前に直す所が分かる（記事末尾の枠 1032px 対 本文 760px）。
  - エラー画面は、ページのチャンクを「同じ番号・中身なし」の JS に差し替えると、どの幅でも1回で出る。構文エラーにする・読み込みを失敗させる方法は、幅によって出ない。
  - layout-shift は画面の外の伸びを数えない。`html` が `scroll-behavior: smooth` のときは、スクロールを `behavior: 'instant'` にして測る。
  - 手元のビルドには広告の中身とアンカー広告が出ない。現場の CLS（0.52）は手元で再現しない（手元は 0〜0.007）。
  - 作業員が動いている間はビルドし直せない。画面を見て直しが出たら、もう1周（止める → ビルド → 起動 → 撮る）が要る。
- 使用量：撮る側 約109,000トークン・94回・約30分／測る側 約101,000トークン・78回・約33分。
- 返した先：記録だけ（もう1回出たら `frontend-build-release-verification.sop.md` に足す）。
