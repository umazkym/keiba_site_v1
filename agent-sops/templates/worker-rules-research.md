# 作業員の決まり（UMA-FREE・<作業の名前>・<日付>）

> ひな形（原本：`agent-sops/templates/worker-rules-research.md`）。指揮役が `<作業フォルダ>/_作業員の決まり.md` に写し、`<…>` を埋め、この囲みを消して使う。決まりそのものを直したいときは、写しではなく原本を直す（`agent-sops/multi-agent-orchestration.sop.md` の 8）。

指揮役（利用者と話す会話）が、観点ごとに作業員を出す。作業員は **1つの観点の1つの段** を受け持ち、最後まで自分の判断で進め、短く報告して終わる。ほかの作業員を待たない。ここは **調べる段** の決まり。

リポジトリ：`<リポジトリの場所>`（Bash では `<リポジトリの場所・Bash の形>`）

## 1. 書いてよい場所
- **自分のフォルダだけ**：`<作業フォルダ>/<観点>/`（指揮役が依頼文で渡す）。一時のファイルもこの中（`_tmp/`）に置く。
- それ以外は **読むだけ**：コード・`agent-sops/`・`.claude/`・`docs/`・記憶・引き継ぎメモ・ほかの作業員のフォルダ・`_data/`
- コードは直さない。直したい所は `施策の案.md` に、ファイルと行を添えて書く（指揮役が利用者と決めてから直す）。

## 2. してはいけないこと（どれも理由がある。回り道もしない）
- **本番（uma-free.com）へアクセスしない**（curl・WebFetch・ブラウザ・スクリプトのどれでも）。2026-09 に自宅の回線が締め出された。
- git の add・commit・push・stash・reset・checkout をしない。GitHub の Workflow を起動しない（`gh workflow run` をしない）。
- DB へつながない。デプロイしない。楽天競馬のリンクを押さない。クラウドや広告の設定を変えない。
- **数字・名前・日付を作らない**。数字には出どころ（ファイルと項目）を書く。確かめていないことは「推測」と書き、何を見れば確かめられるかを添える。
- 鍵・トークンの値、メールアドレス、支払いの個人情報を表示・記録しない。
- 作業員をさらに出さない（Agent 道具を使わない）。
- 開発用サーバー・フロントのビルドと専用 Chrome（ポート 9344）は、依頼文で「担当」と書かれた作業員だけが使う。

## 3. 文脈をあふれさせない（2026-10-02、指揮役も作業員3人もここで止まった）
- **大きなファイルを Read で丸ごと読まない**。3,000行を超えるコードは、Bash の `grep -n` で場所を見つけ、Read は `offset`・`limit` で 200行以内ずつ。
- JSON・TSV・ログ（100KB を超える物）は Read しない。小さな Python スクリプト（**Write 道具で作る**。Bash の heredoc で作らない）を `_tmp/` に置き、要る所だけ取り出して、出力は数十行までにする。長い出力は `_tmp/out_*.txt` に書き、行数だけ見てから要る所を読む。
- GitHub Actions の記録は、ファイルに取ってから grep で読む（`gh run view <番号> --log > _tmp/runs/<番号>.log`）。画面にそのまま出さない。
- 画像（Read）は、要る物を数枚だけ。
- `分析.md`・`施策の案.md` の **初版を早めに書き出す**。追記は小分けにして、作ったらすぐ当てる（`_tmp/` に下書きをためたまま止まると、成果物に入らない）。
- 1つの段で終わる。範囲が広がったら、広げずに報告へ書く。

## 5. 質の決まり
- 始める前に読む：この決まり、依頼文に書かれた物（行の範囲つき）。それ以外を広く読みに行かない。
- すでに分かっていること（記憶・日誌・指揮役の資料）を前提にし、その先を調べる。同じ結論の言い直しで終わらない。
- 事実（数字で確かめたこと）・推論（数字から言えること）・推測（確かめていないこと）を分けて書く。
- Bash は毎回 `cd <リポジトリの場所・Bash の形> &&` で始める。Python の出力は `sys.stdout.reconfigure(encoding="utf-8")`。
- 日本語のパスは、Bash では文字化けし、Grep 道具でも効かないことがある → Glob・Read 道具（絶対パス）か PowerShell で扱う。
- リポジトリ全体への `grep -r` は時間切れになる → `git grep -n "<語>" -- <フォルダ>`。Grep 道具の glob は、波かっこ（`*.{ts,tsx}`）と隠しフォルダで当たらないことがある。
- gh は `export GH_TOKEN=$(gh auth token --user <このリポジトリの GitHub アカウント>)` のあと（読むだけ：`gh run list`・`gh run view`・`gh run download`）。
- 言葉は日本語。専門用語は避けるか、初めに一言で説明する。

## 6. 作る物（自分のフォルダに）
- `分析.md`：事実・推論・推測に分けた本文。表を使う。長くてよい。
- `施策の案.md`：下の形で、効果が大きい順に。
  ```
  ## 案N <一言の題>
  - 何をする：
  - どこを：<ファイル:行、または設定の場所>
  - 根拠：<数字と出どころ>
  - 見込む効果：<大・中・小と、その理由>
  - 手間：<小・中・大>　危なさ：<戻せるか・お金・公開への影響>
  - 確かめ方：<どの数字がどうなれば成功か>
  - 大きさ：<小＝そのまま直せる／中＝利用者に軽く確かめる／大＝許可が要る>
  ```
- `状況.md`：下の形（30行まで。最初に書き、進むたびに直す）。
  ```
  # 状況（<観点>）
  段：<調査｜実装｜点検>（<日時。date で取る>）
  誰の番：<利用者｜指揮役｜作業員>
  次の一手：
  ## できている物
  ## 自分で決めたこと
  ## 覚えること（利用者の好み・学び・次も使える調べ方）
  ## 利用者に聞くこと
  ## 経緯（新しい順・1行ずつ）
  ```
