```python
# backend/scripts/maintenance.py
from database.session import SessionLocal

db = SessionLocal()

# 2年以上前のデータを削除
```

## 10.4 パフォーマンスチューニング

### 10.4.1 スロークエリの検出

**PostgreSQLログ有効化**:
```sql
-- マネージドPostgreSQLではデフォルトで有効
SHOW log_min_duration_statement;
-- 1000ms以上のクエリをログ出力
```

**スロークエリ例**:
```sql
-- 悪い例 (N+1問題)
SELECT * FROM predictions WHERE race_id = '202501150106';
-- 各予測ごとに馬情報を取得 (N回のクエリ)

-- 良い例 (JOIN使用)
SELECT p.*, h.name
FROM predictions p
JOIN horses h ON p.horse_id = h.id
WHERE p.race_id = '202501150106';
```

### 10.4.2 インデックスの追加

```sql
-- レース日付検索の高速化
CREATE INDEX idx_race_date ON races(race_date);

-- 馬ID検索の高速化
CREATE INDEX idx_result_horse_id ON results(horse_id);

-- 複合インデックス
CREATE INDEX idx_race_venue_date ON races(venue_name, race_date);
```

**インデックス確認**:


### 10.4.3 接続プールの最適化

**現在の設定**:
```python
# backend/database/database.py
engine = create_engine(
    DATABASE_URL,
    pool_size=2,           # Cloud Run最小限
    max_overflow=1,        # オーバーフロー1
    pool_recycle=900,      # 15分ごとにリサイクル
    pool_pre_ping=True     # 接続チェック
)
```

**調整のポイント**:
- `pool_size`を増やす → 同時リクエスト増加に対応
- `max_overflow`を増やす → ピーク時の余裕
- GCE e2-microの`max_connections=50`とのバランスに注意

## 10.5 エラー対応

### 10.5.1 よくあるエラーと対処法

#### 1. Network Timeout

**エラーメッセージ**:
```
[ERROR] requests.exceptions.ReadTimeout: HTTPSConnectionPool
```

**原因**: netkeiba.comの応答遅延

**対処法**:
```python
# タイムアウト時間を延長
response = requests.get(url, timeout=60)  # 30秒 → 60秒
```

#### 2. Database Connection Pool Exhausted

**エラーメッセージ**:
```
[ERROR] sqlalchemy.exc.TimeoutError: QueuePool limit exceeded
```

**原因**: 接続数が上限に達した

**対処法**:
```python
# セッションを適切にクローズ
with get_db_session() as db:
    # クエリ実行
    pass
# 自動的にclose()
```

#### 3. Memory Error

**エラーメッセージ**:
```
[ERROR] MemoryError: Unable to allocate array
```

**原因**: メモリ不足 (Cloud Run のメモリ割当上限)

**対処法**:
```python
# バッチサイズを削減
BATCH_SIZE = 10  # 15 → 10

# ガベージコレクション強制実行
import gc
gc.collect()
```

#### 4. Twitter API Rate Limit

**エラーメッセージ**:
```
[ERROR] tweepy.errors.TooManyRequests: 429 Too Many Requests
```

**原因**: Twitter APIのレート制限

**対処法**:
```python
# リトライロジック追加
from tenacity import retry, stop_after_attempt, wait_fixed

@retry(stop=stop_after_attempt(3), wait=wait_fixed(60))
def post_tweet(text):
    api.update_status(text)
```

## 10.8 データ品質管理

### 10.8.1 データ整合性チェック

**定期チェックスクリプト**:
```python
# backend/scripts/data_quality_check.py
from database.session import SessionLocal
from database.models import Race, Result, Prediction

db = SessionLocal()

# チェック1: 予測のないレース
races_without_predictions = db.query(Race).outerjoin(Prediction).filter(
    Prediction.id == None,
    Race.race_date >= datetime.now().date()
).count()

print(f"Races without predictions: {races_without_predictions}")

# チェック2: 結果のないレース (過去分)
races_without_results = db.query(Race).outerjoin(Result).filter(
    Result.id == None,
    Race.race_date < datetime.now().date()
).count()

print(f"Past races without results: {races_without_results}")

# チェック3: 異常な偏差値
abnormal_predictions = db.query(Prediction).filter(
    (Prediction.deviation_score < 0) | (Prediction.deviation_score > 100)
).count()

print(f"Abnormal deviation scores: {abnormal_predictions}")

db.close()
```

実行:
```bash
# 週次で実行
crontab -e
0 9 * * MON python /path/to/data_quality_check.py
```

### 10.8.2 予測精度のトラッキング

**精度レポート生成**:
```python
# backend/scripts/accuracy_report.py
from database.session import SessionLocal
from database.models import Prediction, Result
from datetime import datetime, timedelta

db = SessionLocal()

# 過去30日間の精度
date_from = datetime.now().date() - timedelta(days=30)

predictions = db.query(Prediction).join(Result).filter(
    Result.race.race_date >= date_from,
    Prediction.mark == '◎'
).all()

first_place_count = sum(1 for p in predictions if p.result.rank == '1')
accuracy = first_place_count / len(predictions) if predictions else 0

print(f"◎ First Place Rate (30 days): {accuracy:.2%}")

db.close()
```

## 10.10 障害対応フローチャート

```
障害発生
  ↓
影響範囲確認
  ├─ フロントエンドのみ → Cloud Run `keiba-frontend-v1` のログとCloudflareの状態を確認
  ├─ APIのみ → Cloud Runログ確認
  ├─ DB接続エラー → GCE VMのステータス確認
  └─ 全体 → GCPインフラ障害の可能性
       ↓
    ログ分析
       ├─ Network Error → GCE VPNファイアウォール確認
       ├─ Database Error → PostgreSQLサービス確認 / 接続プール確認
       ├─ Memory Error → バッチサイズ削減
       └─ Logic Error → バグ修正 / デプロイ
          ↓
       修正実施
          ↓
       動作確認
          ↓
    ポストモーテム作成
       - 原因
       - 影響範囲
       - 対処内容
       - 再発防止策
```
