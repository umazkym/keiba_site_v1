# スマホデザイン改修の引き継ぎと検証（2026-09-25）

Claudeの未コミット変更を保持し、13画面の仕上げを実施。最新の利用者指示を優先し、個別レースと開催日ボードでは当該レースの結果を表示せず、AI偏差値の提示に統一する。

## 表示仕様

- 実着順列、着順順の並べ替え、勝ち馬、結果確定ラベル、レース結果カードを除去。結果入りデータでも画面はAI偏差値順または馬番順。
- 馬名はカタカナ2〜9文字を基準に全文を表示。出走表15px、注目馬カード22pxなど既存の文字サイズを保ち、狭い場所は折り返す。ホーム、開催日ボード、重賞カード、記事内の予測導線、次レースの馬名も省略しない。
- 非常に狭いスマホ対戦表の行見出しは、利用者が許容した「馬番＋先頭3文字」。省略記号は付けず、読み上げと対戦詳細には全文を残す。PCの対戦表は全文で折り返す。
- 過去対戦の集計、騎手・コースの履歴、サイト全体の成績ページは既存の分析用途を維持する。当該レースのAI偏差値表へ実着順は並べない。
- API形式、DBスキーマ、公開側の404条件は変更しない。

## 仕上げで修正した問題

| 場所 | 修正 | 理由 |
| --- | --- | --- |
| ヘッダー | モバイルの操作行を44pxへ | 44pxの検索・メニュー操作が画面上端からはみ出さない |
| パンくず | リンクに実寸44pxを確保 | 疑似要素を固定ヘッダーへ重ねない |
| 見出しの右リンク | 実寸44px、上下中央配置 | 「すべて見る」の疑似領域が直下の記事へ7〜8px重なっていたため |
| フッターSNS | 幅・高さとも44px以上 | 1文字のXリンクも同じ操作基準へ統一 |
| `hit-44` | 最小44pxと変形を含めた領域へ整理 | 横方向の一律拡張による隣接操作の重なりを防ぐ |
| レース選択 | 要約44px＋番号44px、枠は内側に描画 | 88px以内で全12Rを1行に収める |
| AI偏差値表 | 着順列を廃止、馬名は折り返し | 誤解につながる結果併記をなくし、9文字まで読める幅を確保 |
| AI偏差値の説明 | 見出しと「?」を一つの高さ44pxボタンへ | 疑似要素が表の枠に切られる問題を、実際のヒット判定で確認して解消 |
| 対戦表 | モバイルは5×5、各マス44px | 密集した操作を解消。狭い行見出しは3文字表示 |
| ホーム会場カード | 1280px未満は2列、コース図は内幅35%以下 | 768px・4会場時の横はみ出し10pxを修正 |
| ホームの320px表示 | 下部導線は「全レースを確認する」、分析ラベルは折り返し可 | 省略記号で操作名や分析名を欠かさない |
| 開催なし | 当日付近の空データで検証 | 過去の撮影は遠い日付の404で、空状態を再現できていなかった |

Claudeの共通余白、記事、FAQ、データタブ、メニュー、PR、広告待ち面の改修も引き継いだ。見本の固定値・ダミーデータより実際の可変長データと最新指示を優先する。

## 検証条件

- 375px・390px：全13画面をWebKitで撮影。各スクロール位置の固定ヘッダー、レース選択、下ナビ、メニューの層を記録。
- 320px：全13画面。768px：全13画面。1024px・1440px：メニューパネルを除く12画面（この幅では常設ナビ）。768px以上はChromium。
- 保存領域は撮影ごとに初期化。広告・計測の外部通信は遮断。全体画像に加え、固定UIはビューポート画像を正とする。
- 1440px画面の200%拡大相当：720×450 CSS px・描画倍率2、動きを減らす設定でホーム・レース・記事・FAQのキーボード到達性を確認。
- 馬名2文字／9文字、18頭、長いレース名、AI偏差値と位置取りの欠損をローカルの架空データで確認。本番データは書き換えない。
- ホームの注目馬カードは画面内の名前だけを2文字／9文字に差し替え、全6幅で全文と文字サイズ維持を確認（`names/report.json`）。

## 操作と広告

- メニューの開閉、フォーカス循環、Escape、背景タップ、閉じた後のフォーカス・スクロール復帰。
- 騎手・コースの全データタブ、矢印/Homeキー、非選択データのDOM保持。
- FAQの初期1問、開閉、カテゴリ切り替えと復帰。
- AI偏差値順／馬番順、12Rへの切り替えと戻る、結果入りデータからの着順非表示。
- 開催なしの200と当日への導線、存在しないURLの404。
- 模擬アンカー広告100pxの表示中はホームCTA・レース下ナビを退避し、解除後に復帰。スクロール位置とページ高の不要な変動なし。
- 未配信状態へ切り替えても広告予約高250pxを維持。

44pxは通常のモバイル操作で確保する。1〜12Rは全番号を同じ行に表示するため幅44px未満・高さ44pxとする。本文中のリンクは文章の行高を維持する。固定下部導線がスクロール中の本文へ重なることやメニュー暗幕は意図した層であり、隣接ボタン同士の当たり判定の重なりと区別する。

## 再確認と引き継ぎ

検証用APIは `.local/design-portfolio/impl/qa-api.cjs`（127.0.0.1:8000）。ローカル本番サーバーは `INTERNAL_API_BASE_URL=http://127.0.0.1:8000` を付けて3101で起動する。比較ページはファイルで開ける。撮影は `qa_capture.py`、実操作は `qa_interactions.py`、比較資料生成は `build_review.cjs`。

再利用する手順知：ビルド後にコードが変わったら、そのビルドの撮影を完成版と扱わない。空状態のURLはHTTPステータスと案内本文を確認する。タップ領域は疑似要素・変形も含め、隣接リンクとの交差を測る。スムーズスクロール中の画面を撮らず、停止後の位置を記録する。SOP更新候補として残す。

撮影JSONには各条件のビルドIDを保存する。全76条件が同じ最終ビルドであること、375/390pxのスクロール位置156件が末尾まで含まれることを確認する。

実機Safari/Android、実際の広告配信、利用者の誤タップ率は未検証。コミット・push・デプロイは行わず、利用者が比較資料を確認して実施する。
